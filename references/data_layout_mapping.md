# 数据形态到 Bento Grid 拓扑容器专家映射规范 (Data-to-Bento Mapping)

在制作商业经营汇报、技术架构、财务分析等演示文稿时，大模型在阶段 3（策划稿）应依据**输入数据的几何特征与业务意图**，直接映射为以下 5 种经典的 Bento 拓扑容器，避免凭空发挥导致排版失调。

---

## 一、 5 大核心业务形态映射模型

### 1. 渠道矩阵 / 多维对比数据 ➔ 【Header总览 + 横向多轨条形图 + 告警沙箱】
* **典型输入**：多渠道销量分布、多区域业绩、多竞品对比表。
* **拓扑结构**：
  - **顶部 (y: 40~110)**：大标题 + 核心大盘指标（如：总出货量、总销售额、全盘 ASP）。
  - **左侧大卡片 (w: 740, h: 535)**：横向条形占比图，逐行对比各渠道的“绝对值、份额条形图、客单价”。
  - **右侧双卡片 (w: 400, h: 255/260)**：
    - 上卡：核心现金牛渠道（如京东自营）稳定特征；
    - 下卡：高增速/异动渠道（如抖音/PDD）特定打法。

### 2. 系统架构 / 业务上下游链路 ➔ 【经典 3+1 架构（左三层垂直堆叠 + 右贯穿护栏）】
* **典型输入**：AI 系统分层、技术栈架构、供应链全链路。
* **拓扑结构**（原作者 Dify 案例标准模板）：
  - **左侧三层 (w: 760, 纵向堆叠)**：
    - 底层 (y: 480)：基础底座（存储/芯片组微缩 Token）；
    - 中层 (y: 300)：数据处理/流水线（节点连线微缩 Token）；
    - 顶层 (y: 120)：业务编排/交互（DSL 拓扑控制微缩 Token）。
  - **右侧贯通卡片 (w: 380, h: 540)**：采用发光虚线框，表示“安全屏障”、“全链路监控”或“顶层治理”。

### 3. 业务问题诊断 / 经营失血分析 ➔ 【2 × 2 四象限矩阵 或 3 问题 + 1 破局】
* **典型输入**：天猫颓势诊断、项目交付延期根因、业务瓶颈。
* **拓扑结构**：
  - **象限 1（致命断层）**：红/青微缩芯片，列举 0 销量或缺失业务；
  - **象限 2（结构畸变）**：单品过高依赖度进度条；
  - **象限 3（高客单失守）**：各渠道高客单出货柱状对比图；
  - **象限 4（破局路线）**：垂直虚线沙箱，列举 3 步突围动作（流水线 Token）。

### 4. 财务三张表 / 经营绩效 ➔ 【单大焦点 Hero + 底部三指标卡】
* **典型输入**：年度财报摘要、毛利与净利分解、现金流走势。
* **拓扑结构**：
  - **上部 Hero 卡片 (w: 1200, h: 280)**：年度核心营收大数字 + 阶段柱状图/面积图趋势。
  - **下部三等分卡片 (各 w: 384, h: 250)**：分别承载盈利能力、运营效率、风险敞口。

### 5. 战略路线图 / 行动决议 ➔ 【三栏里程碑 + 底部时间轴横幅】
* **典型输入**：OKR 落地决议、未来 30 天行动路线、四阶段发展规划。
* **拓扑结构**：
  - **主体三列 (各 w: 366, h: 425)**：三大战略支柱（守正、突击、防护），内部包含 3 个带强调序号的行动点。
  - **底部横幅 (w: 1160, h: 85)**：横向时间轴，串联第 1 周、第 2 周、第 4 周的关键里程碑节点。
